# API 测试规范指南

## 概述

本文档规定了Faker Agent项目中API开发和测试的标准流程和规范要求。所有开发的API接口必须经过严格的测试和验证，以确保功能正确、性能良好、文档完善。

## API测试要求

### 1. 强制使用curl命令测试

所有开发的API接口**必须**使用curl命令进行测试，并将测试命令和结果记录在相关文档中。这一要求有以下几个目的：

- 确保API接口可以在没有特定客户端的情况下被正确访问
- 提供清晰的接口调用示例，方便其他开发者理解和使用
- 作为回归测试的基础，便于后续验证接口是否正常工作

### 2. 测试覆盖范围

每个API接口的测试应该覆盖以下方面：

- **基本功能测试**：验证接口按照预期工作
- **错误处理测试**：验证接口能够正确处理错误情况
- **边界条件测试**：验证接口能够处理边界值
- **性能测试**：验证接口响应时间在可接受范围内

### 3. 测试文档要求

每个API接口的测试文档应包含以下内容：

- API接口的完整URL
- 请求方法（GET、POST、PUT、DELETE等）
- 请求头信息
- 请求参数（URL参数、请求体）
- 期望的响应状态码
- 期望的响应体
- 完整的curl命令示例
- 实际响应结果示例

## curl命令测试规范

### 基本格式

```bash
curl -X [METHOD] "[URL]" \
  -H "Content-Type: application/json" \
  [其他请求头] \
  -d '[请求体JSON]' \
  -v
```

### 通用参数说明

- `-X [METHOD]`：指定HTTP方法（GET、POST、PUT、DELETE等）
- `-H "[Header]"`：指定请求头
- `-d '[DATA]'`：指定请求体数据（JSON格式）
- `-v`：详细输出，包括请求和响应的头信息

### 示例

以下是几种常见API测试的curl命令示例：

#### GET请求示例

```bash
# 获取工具列表
curl -X GET "http://localhost:8000/api/tools" \
  -H "Content-Type: application/json" \
  -v
```

#### POST请求示例

```bash
# 提交任务给agent
curl -X POST "http://localhost:8000/api/agent/task" \
  -H "Content-Type: application/json" \
  -d '{"query": "What is the weather in Beijing today?", "context": {}}' \
  -v
```

#### 带参数的GET请求示例

```bash
# 获取会话列表（带分页参数）
curl -X GET "http://localhost:8000/api/conversations?skip=0&limit=10" \
  -H "Content-Type: application/json" \
  -v
```

## 测试结果验证

测试结果应该从以下几个方面进行验证：

1. **状态码验证**：确保接口返回正确的HTTP状态码
2. **响应格式验证**：确保响应格式符合API规范（通常是JSON格式）
3. **内容验证**：确保响应内容包含预期的数据
4. **性能验证**：确保响应时间在可接受范围内

## 持续集成测试

所有API测试应该集成到持续集成流程中，确保每次代码变更后都能自动执行测试并验证结果。

## 问题排查

当API测试失败时，应该从以下几个方面进行排查：

1. **请求格式是否正确**：检查URL、请求头、请求体等
2. **服务器是否正常运行**：检查服务器日志
3. **依赖服务是否可用**：检查依赖的数据库、缓存等服务
4. **网络连接是否正常**：检查网络连接和防火墙设置

## 结论

严格遵循本文档规定的API测试规范，可以确保Faker Agent项目中的API接口质量，提高开发效率，减少生产环境中的问题。所有开发人员必须在开发新API或修改现有API时，按照本规范进行测试和验证。
